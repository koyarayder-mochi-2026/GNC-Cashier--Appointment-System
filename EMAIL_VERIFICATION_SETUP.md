# GNC student email verification setup

## Required Supabase URL configuration

In Supabase Dashboard → Authentication → URL Configuration, set:

- **Site URL:** `https://gnc-cashier-appointment-system.vercel.app`
- **Redirect URL allow-list:** `https://gnc-cashier-appointment-system.vercel.app/email-verified.html`

For local development only, add the exact local callback URL that you run (for example `http://localhost:5500/email-verified.html`) as an additional Redirect URL. Do not use a localhost Site URL for the live student website.

## Frontend behavior

`config.js` explicitly sets:

`emailRedirectUrl: 'https://gnc-cashier-appointment-system.vercel.app/email-verified.html'`

Both signup and resend-verification use this exact URL. They no longer derive the callback from `window.location.origin`, which was causing emails generated on `localhost:3000` to send students back to a local server that was no longer running.

For the normal student workflow, students should register and request/resend confirmation from the deployed Vercel website, not a localhost development server. The PKCE verification code is tied to the browser origin where signup began; therefore the signup and callback should use the same deployed domain. If an email was generated by an older localhost build, that old link cannot be rewritten. Open the live GNC portal, use **Resend verification email**, and click the newest email.

## Callback handling

`email-verified.html` is the branded confirmation page. `email-verified.js` explicitly exchanges Supabase's `?code=...` PKCE callback using `exchangeCodeForSession`, supports `token_hash` callbacks, checks that the user has a confirmed email, then clears the temporary local callback session. On success it shows **“Your email is now verified”** and a button to `/?verified=1#authPanel`, where the main GNC portal opens the Login tab and shows a confirmation message.

## Important: update the Supabase confirmation email template

To make verification work even when a student starts registration on a local development address or opens the email in a different browser context, use the Supabase token-hash confirmation link instead of `{{ .ConfirmationURL }}`.

In Supabase Dashboard → Authentication → Email Templates → **Confirm signup**, replace the confirmation link in the template with this exact anchor:

```html
<a href="https://gnc-cashier-appointment-system.vercel.app/email-verified.html?token_hash={{ .TokenHash }}&amp;type=signup">Confirm email address</a>
```

You can keep the rest of Supabase's email wording. Do not use `{{ .ConfirmationURL }}` in this confirmation template when using this direct token-hash callback. The GNC callback calls Supabase `verifyOtp({ token_hash, type: 'signup' })`, so it verifies the email securely without needing the PKCE verifier stored on the original localhost/browser origin.

The frontend still passes the fixed production `emailRedirectTo` as a fallback for Supabase-generated confirmation URLs. Existing emails already sent with the old localhost link cannot be changed; request a new verification email after deploying the updated code and saving this template.

## Test procedure

1. Deploy the updated project, including `config.js`, `app.js`, `email-verified.html`, and `email-verified.js`.
2. Confirm the Site URL and Redirect URL allow-list above in Supabase.
3. Open `https://gnc-cashier-appointment-system.vercel.app` (not localhost).
4. Register a new test student. Supabase sends a confirmation email with the deployed callback URL.
5. Click the newest email in the same browser used to register.
6. The browser should open `/email-verified.html`, exchange the PKCE code, and display the verified success message.
7. Click **Continue to sign in**. The main portal should open with Login selected and a success message.
8. Sign in with the registered email and password.

If an old email points to localhost, do not keep clicking that old link. It was generated by the previous local build; request a fresh email from the deployed website after deployment.
